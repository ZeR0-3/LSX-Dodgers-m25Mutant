## 1. 普通に使えるメモリ(TPA)

- COM は `0100H` から読まれる。使える範囲は **`0100H`〜`(0006H)` の値 − 1**。この移植では `(0006H)=E000H` なので `0100H-DFFFH`(約55.75KB)。**上端は固定値で書かず、`0006H` を読む。**
- `E000H` 以降は OS の共通領域(ゲート、DPB、バッファ)。**読み書きしない**(ただし 5 節の `ramdisk` が F: の DPB を書く例外がある)。
- `0000H-00FFH` は CP/M の通常のゼロページ(`0005H`=BDOS 入口、`005CH`=FCB、`0080H`=コマンド行。**コマンド行は127文字まで**)。
- スタックは自分で決める(`ld sp,...`)。**窓(4 節)にしたバンクには置かない。**
- CCP の `$` は `$$`、バッチやコマンド行の注意は `docs/man.md` を参照。

## 2. TPA の外にあるメモリ(物理ページ)

CPU は 64KB を **8KB のバンク8枚**(0000H, 2000H, … E000H)に分け、各バンクにどの**物理ページ**(8KB)を見せるかを MMU が決める。`B4h` でバンク番号、`B5h` でそのバンクのページを書く。

| 物理ページ | 内容 | 使えるか |
|---|---|---|
| 00-05, 0A | TPA(バンク0-6 の通常のページ) | プログラムそのもの |
| 06, 0B-0F | OS(カーネルのバンク6/5、IOCS退避、オーバーレイ、共通) | **触らない** |
| **07, 08, 09** | **空き 24KB**(LSX は使っていない) | 予約して使える。※実機の IPL ROM / IOCS が使っていないかは**未確認** |
| 10h-1Fh | 拡張RAM 128KB。**F: RAMディスクが先頭から N ページ使う**(`ramdisk` で 0-16 に変えられる) | F: の外は予約して使える。拡張RAMが無い機械では 5(無い) |
| 20h以上 | ROM・VRAM など | 使えない(E1h が 5 を返す) |
| EMM(E:) | ページではなくポート I/O(`ACh`/`ADh`)の別メモリ。64KB単位 | E: が使っている。プログラムが直接使うなら E: を使わない前提 |

つまり**大きなデータ置き場**として、最大で 24KB(07h-09h)+(128KB − F: の分)を取れる。F: を 0 にすれば 152KB。

## 3. 呼び出し(BDOS `C=E0h`〜`E3h`)

すべて `call 5`。成功は **A=0**。ポインタを取らないので、どこから呼んでもよい。

| C | 名前 | 入力 | 出力 |
|---|---|---|---|
| E0h | SYSINFO | — | B=機能ビット(0:IOCS 1:EMM(E:) 2:RAMディスク(F:) 3:SASI(H:) 4:漢字 5:G:(今は0) 6:ページ管理) C=EMMの64KB数 D=F:のページ数 E=この拡張の版(2) HL=TPA上端+1(E000H) |
| E1h | PAGEINFO | E=ページ(0-3Fh) | B=所有者 0:空き 1:OS 2:TPA 3:F: 4:予約済み 5:無い/使えない |
| E2h | PAGEALLOC | E=ページ、または FFh(空きの最小) | B=ページ。失敗は A=F0h |
| E3h | PAGEFREE | E=ページ(自分で予約したもの) | 失敗は A=F0h |

- **LSX かどうかの判定**: `C=6Fh`(MSX-DOS 版の取得)で `L=4`(機種ID)を確かめ、`E0h` が `A=0` かつ `HL=E000H` で返ること。それ以外の環境(素の CP/M など)で `E0h` を呼ぶと何が起きるかは**確認していない**ので、先に 6Fh で機種を確かめること。
- 予約したページは、**次のプログラムを起動する直前にすべて自動で解放**される(プログラムが終了しても、次のコマンドまでは予約が残るだけ)。自分の終了時に E3h で返すのが礼儀。
- 予約は「他のプログラムや OS と取り合わないための印」でしかない。ページの中身は予約しても消えない・初期化されない。
- **F: の中身は、予約できる範囲(F: の外)なら無関係。** 予約できない範囲(F: 内)を MMU で直接触ると F: を壊す。必ず E1h/E2h を通す。

## 4. ページの使い方(窓)— ここが一番大事

予約したページを使うには、自分でバンクの1つを**窓**にして、そのページを CPU から見えるようにする。

```
; 窓を開ける(バンク3 = 6000H-7FFFH にページ pg を出す)
di
ld a,3 : out (0B4h),a        ; バンク3を選ぶ
in a,(0B5h) : ld (orig),a    ; 元のページを覚える
ld a,3 : out (0B4h),a        ; ← 読むと B4h が進むので選び直す
ld a,(pg) : out (0B5h),a     ; 窓にページを出す
; … 6000H-7FFFH を読み書き …
ld a,3 : out (0B4h),a        ; 閉じる
ld a,(orig) : out (0B5h),a   ; 元のページへ
ei
```
(動く例: `tests/pgwin.asm`、OS 内の例: `src/M25MEM.ASM` の RDRD/RDWT。)

**守ること**

1. **窓がバンク4(8000H-9FFFH)なら、BDOS は窓を開いたまま呼んでよい(エミュレータで確認: `tests/pgbank4.asm`)。** BDOS のゲートが入れ替えるのはバンク5/6 だけで、バンク4 は触らない。ただし BDOS に渡すバッファ・FCB・DMA は窓の外に置くこと(窓の中を指すと窓のページの中身が読み書きされる)。
   **バンク1-3 を窓にしたときは BDOS を呼ぶ前に閉じる**(OS 内のドライバがバンク1/3 を窓に使う、IOCS はバンク1-3 を ROM に替える)。**IOCS(`rst 18h`)は窓の種類にかかわらず呼ぶ前に閉じる**: 戻りでバンク2-6 がユーザの既定のページに戻される(コードで確認。窓を開けたままの動作は未試験)。
   なお COM の読み込み(ローダ)はバンク4 を使う(読み込みの間だけ。プログラムの実行前)ので、実行中のプログラムには関係しない。
2. **窓を開けている間は `DI`。** その間は CALL/PUSH/POP/RET も使わない(スタックが窓のバンクにあると壊れる)。窓の中でやるのは LDIR などの単純なコピーに限る。
3. **窓にするバンクにコード・スタック・転送元/先のバッファを置かない。**
4. `B5h` は**書いても読んでも `B4h`(選択)が +1 される**。読んだら必ず `B4h` を選び直してから書く。
5. 窓にするバンクは、プログラムが載っていないものを選ぶ。小さい COM(~8KB)ならバンク1-3(2000H-7FFFH)が空く。大きいプログラムでコードがバンク0-3 に載るなら、窓は**バンク4(8000H-9FFFH)**が最適(BDOS をまたいで開けたままにできる。`pglib.inc` は `PGBANK equ 4` で使う)。
6. IOCS を呼ぶ間はバンク1-3 が ROM、バンク6 が VRAM に替わる。IOCS を呼ぶ側のコード・スタックをそこに置かない。

**ライブラリ `coms/pglib.inc`(試験済み)**: 窓の開閉を1つの呼び出しにしたもの。
`pgread` / `pgwrite`: `A`=物理ページ、`HL`=ページ内オフセット(0-1FFFH)、`DE`=読み込み先/書き込み元(TPA内)、`BC`=バイト数。
戻りは CF=0 成功、CF=1 失敗(オフセット+バイト数が 2000H を越える。何もしない)。割り込みは呼ぶ前の状態に戻る。
窓のバンクは `PGBANK`(既定 3 = 6000H-7FFFH。include の前に `PGBANK equ 4` などで替えられる)。使い方の例と試験は `tests/pgtest.asm`
(`E2h` で予約 → 書く → BDOS を呼ぶ → 読み戻して比較 → `E3h` で解放)。C から使うなら、この2つを呼ぶ小さな C 用ラッパを書く。

**エディタ向けの作り方の目安**: ページに直接ポインタを持つのではなく、`pgread(page, offset, buf, len)` / `pgwrite(...)` の2関数(窓を開く→ LDIR → 閉じる、を1つにしたもの)を共通コードにして、**TPA 内の作業バッファ(1行・1画面ぶんなど)とページの間でコピーする**。この形なら 1 〜 6 を関数の中に閉じ込められ、呼び出し側は窓を意識しない。ギャップバッファや行ポインタ表(各行の(ページ,オフセット))を 07h-09h・拡張RAM に置く構成が作りやすい。

## 5. RAM ディスク(F:)を小さくして拡張RAMを空ける

- ユーザ向け: `ramdisk 32`(KB、8の倍数、0-128)。**F: はフォーマットされ、中身は消える。** 0 で F: を使わない。128 で元に戻る。大きさは F: 先頭に保存され、リセットしても拡張RAMが残っていれば引き継ぐ(0 にすると保存を消すので、次の電源投入で 128KB に戻る)。`ramdisk` だけで現在値を表示。
- **アプリが勝手に F: を縮めない。** ユーザのデータを消すので、エディタは「拡張RAMを使うには `ramdisk 64` などで F: を小さくしてください」と案内するにとどめるのが安全。
- しくみ(他のプログラムが同じことをするなら): BDOS 呼び出しではなく、共通領域にある F: の DPB(`F2A0H` から32バイト)を直接書き換える。`F2A0H`=FATLN(0 で F: を使わない)、`F2A8H`=MAXCL(=16N−8)、`F2B6H`=ページ数N、`F2B8H`=拡張RAMあり(1)、`F2BAH`=SDIR(0)。手順は `coms/ramdisk.asm` の `fmt` を参照。
- E1h の所有者(3=F:)は `F2B6H` の N から決まる。

## 6. IOCS・キーボード・画面との関係

- LSX は IOCS(`rst 18h` + 関数番号)を IPL ROM の IOCS が使える機械では使う。呼ぶ間は割り込みが許可され、バンク1-3/6 が替わる(上の 4 節の 1・6)。
- 画面・キー入力は普通は BDOS(`C=2,6,9,10` など)を使えばよく、直接 IOCS や VRAM(ページ38h)を触る必要はない。`mode 40|80` で桁数が変わる。
- 漢字は Shift_JIS。`kmode` で表示の ON/OFF。

## 7. sdcc 移植のメモ(未着手の方針)

- CP/M 形式の COM(`0100H` 開始、ORG 0100H)として出すなら、`crt0` で `ld sp,` を決めて `main` を呼び、`jp 0`(ウォームブート)で終わる。
- 64KB を超える・拡張メモリを使うデータは、**4 節の `pgread/pgwrite` 方式**にして、C からは普通の関数として呼ぶ(ニアデータは TPA、遠いデータはページ)。バンク切り替えコードの呼び出し(banked call)は、窓を閉じて BDOS を呼ぶ規則と衝突しやすいので、最初は採用しないほうがよい。
- BDOS 呼び出しは C の関数にせず、レジスタを直接渡すアセンブラの小関数にする。
