# システム情報とページの予約(BDOS E0h-E3h)と子プログラムの起動(E5h)  2026-11-12

他のソフト(大きなエディタ、コンパイラなど)が「拡張メモリを使ってよいか」を OS に聞き、使うページを届けるための呼び出し。
エミュレータでの確認だけ。実機は未確認。実装: `src/M25RES.ASM`(常駐)、確認用 `coms/sysinfo.asm`、試験用 `tests/pgwin.asm`。

## 呼び出し(C=番号。成功は A=0)
| 番号 | 名前 | 入力 | 出力 |
|---|---|---|---|
| E0h | SYSINFO | — | D=F:のページ数 B=機能ビット(0:IOCS 1:EMM(E:) 2:RAMディスク(F:) 3:SASI(H:) 4:漢字表示 5:GVRAMドライブ(G:)=今は0 6:ページ管理) C=EMMの大きさ(64KB単位) E=この拡張の版(3。E5h EXEC あり) HL=TPAの上端+1(E000H) |
| E1h | PAGEINFO | E=物理ページ(0-3Fh) | B=所有者 0:空き 1:OS 2:TPA 3:RAMディスク(F:) 4:予約済み 5:無い/使えない |
| E2h | PAGEALLOC | E=ページ、または FFh(空きの最小) | B=ページ。失敗は A=F0h |
| E3h | PAGEFREE | E=ページ(自分で予約したもの) | 失敗は A=F0h |
| E5h | EXEC | DE=コマンド行(00h/0Dh終端、79文字まで。内部コマンドまたはCOM。.BATは未対応) | 子の終了後に A=終了コード(0=正常、1=コマンドの失敗、他は子の 62h の B)。起動できなければ A=F0h(空きページが7枚ない) F1h(入れ子が4段を越える)。BC=DE=HL=0 |
| E4h | LNAMEREG | DE=FCB(名前を 8+3 で入れたもの)、HL=名前の9文字目以降(10バイト、余りは00h) | A=0。長いファイル名(`docs/longname.md`)を FCB に結びつける |
- ポインタを取らないので、ユーザのゲート(UGATE)でバウンスは要らない。BDOS 6Fh(`_DOSVER`)は変えていない(L=4 が機種ID)。
- 予約したページは **次のプログラムを起動する直前(`LOADCOM`)にすべて解放**される。解放し忘れても次のコマンドでは空きに戻る。
- IOCSOK(IPL ROM の有無)は ROM 無しの簡易IPLで N になる(エミュレータで確認)。

## どのページが使えるか
- 物理ページ 00-0F はメイン RAM。`PGMAIN`(M25RES.ASM)が所有者を決めている: 00-05 と 0A = TPA、06 と 0B-0F = OS(カーネルのバンク6/5、IOCS退避、オーバーレイ、共通)、**07-08 = 空き(16KB)**、09 = オーバーレイ1(E5h EXEC の準備と後始末。以前は空きだったが、常駐の共通領域に入りきらず1枚使った)。
  - 07-08 は LSX のソースでは使っていない(grep)。エミュレータでは `pgwin f`(書く)→ `dir`、`mode 40`、`mode 80`、`color`、ファイル出力 → `pgwin v`(確かめる)で壊れないことを確認した(IPL ROM は実IPL)。**実機で IPL ROM / IOCS が使っていないかは未確認。**
- 10h-1Fh(拡張RAM 128KB)は、RAMディスク(F:)の使っているページだけ所有者3(予約不可)。F: の外は空き(または予約済み)。拡張RAMが無ければ 5。
- **F: の縮小・無効化**: `ramdisk 32`(KB。8の倍数、0-128。0 で F: を使わない)。F: はフォーマットされ(中身は消える)、使わなくなったページは空きになって E2h で予約できる。大きさは F: 先頭(ページ10h)に保存され、リセットしても拡張RAMが残っていれば引き継ぐ。0 にするとその保存を消すので、次に電源を入れ直すと 128KB で作り直される。
  - しくみ(常駐部の空きがないので BDOS 呼び出しは増やしていない): F: の状態は共通領域(E000H以降)の F: のDPB(F2A0H から32バイト)にある。`ramdisk` は F2A0H(FATLN: 0 で F: を使わない)、F2A8H(MAXCL=16N-8)、F2BAH(SDIR=0)、F2B6H(ページ数N。DPBの未使用領域)を書き換える。F2B8H(拡張RAMがあれば1)は起動時に設定される。E1h の所有者はF2B6Hから決まる。
  - 他のプログラムが同じことをするなら、`coms/ramdisk.asm` の `fmt` と同じ手順(ページ10hをバンク3へ割り当て、セクタ0-9を0にして、タグ+ページ数+FAT先頭を書く → DPBを書き換える)にすること。プログラムが拡張RAMのページを予約中だと `ramdisk` は何もしない。
- EMM はポート I/O(ACh/ADh)でページではない。E: が使っているので、プログラムが直接使うなら E: を使わない前提で。
- 20h以上(ROM・VRAM など)は 5。

## ページの使い方(MMU の窓)
予約したページを実際に使うには、自分で `B4h`(バンク番号)と `B5h`(ページ)を書く。守ること:
1. **窓がバンク4 なら BDOS は開いたまま呼んでよい**(`tests/pgbank4.asm` で確認。`UCPIN` は COM 読み込み専用でプログラム実行中は無関係)。BDOS に渡すバッファは窓の外に置く。**バンク1-3 の窓と IOCS 呼び出しは、呼ぶ前に窓を元のページに戻す**(IOCS の戻りでバンク2-6 が既定に戻る)。
2. 窓を開く前に `B5h` を読んで元のページを覚える。読むと `B4h` が進むので、書く前に `B4h` を選び直す(`tests/pgwin.asm` の `opn`/`cls`)。
3. 窓にしたバンクにある自分のコードは実行できなくなる。窓にするバンクにはコードを置かない。TPA のバンク0-3(0000H-7FFFH)に大きなコードを置くなら、窓には **バンク4(8000H-9FFFH)** を使うのが現実的(バンク4 は TPA だが、OS の本体は 5/6/7 にあり、窓の間 OS を呼ばなければ問題ない)。
4. 窓を開いている間は `DI`。割り込みハンドラは共通バンク(E000H以降)にあるので、窓があっても動くが、スタックは窓のバンクに置かない。
5. IOCS を呼ぶ間はバンク1-3 が ROM に替わる(`docs/hardware-notes.md`)。

## E4h LNAMEREG(長いファイル名)
`FCB` には 8+3 の11バイトしか入らないので、名前の9文字目以降(name2)は別に渡す。FCB に name1+ext を入れ、E4h で name2 を登録してから、同じ FCB(名前は変えない)で 0Fh(開く)・11h(検索)・13h(削除)・16h(作成)・17h(名前変更)を呼ぶと、長い名前として扱う。登録は新しい4つの FCB まで有効(FCB の住所と名前11バイトが同じ間)。登録しない FCB は name2 が空の名前として扱われ、長い名前のファイルには一致しない。検索結果(DTA)の name2 は +0Ch の10バイト(`dtabuf+13`)。使い方の例は `tests/lnreg.asm`。

## E5h EXEC(子プログラムの起動。親のメモリに触れない)
`:!cmd` やファイルセレクタ型の環境から、外部コマンドを動かして戻ってくるための呼び出し。CP/M の COM は 0100H 固定で再配置できないので、**子には空きページ7枚をバンク0-6 に出して 0100H から動かす**(親のページは動かさない・コピーしない)。エミュレータでの確認だけ。実機は未確認。実装: `src/M25OVL.ASM`(`RS_EXEC` / `PEXIT` / `SETBK04`)、`src/M25PROC.ASM`(オーバーレイ1)、`src/M25GATE.ASM`(`UXRET`、`UWBOOT` の分岐)。試験: `tests/exectest.asm` `execchild.asm` `execfail.asm` `nestp.asm` `nestc.asm`(`tools/test_all.sh`)。

- **呼び方**: `ld c,0E5h` `ld de,コマンド行` `call 5`。戻りは子の終了後(`jp 0`、BDOS 0、62h)。DE は 9F00H 以上でもよい(ゲートがバウンスする)。
- **必要なもの**: 空きページ7枚(07h-08h と拡張RAMのうち F: が使わない分、ほかのプログラムが予約していない分)。F: が既定の128KBだと足りないので、呼ぶ前に `ramdisk 64` などで F: を縮める(アプリが勝手に縮めない。足りなければ A=F0h を見て案内する)。
- **親に起きないこと**: 親の TPA・ゼロページ・予約したページ・SP・割り込み状態・DMA は、子が何を書いても変わらない(子は別のページを見ている)。親が予約したページは、子から見ると「予約済み」で、子は E3h で返せない。
- **子の起動**: 子の 0000H-00FFH は親のゼロページの写しから始まる(0000H の JP、0005H の JP、0038H、0004H のドライブ)。コマンド行・FCB は CCP と同じ手順で子のゼロページに作る。子の stack は E000H から。
- **終了コード**: 子が 62h(_TERM)で B を返せばそれ、`jp 0` なら 0。コマンドが失敗(見つからない・読み込めない)なら 1(「Error!」が出る)。戻ったあとの `$?`(CCP の終了コード)は 0。
- **入れ子**: 子から E5h を呼べる。4段まで(5段目は A=F1h)。ページは1段ごとに7枚。
- **リダイレクト/パイプ**: コマンド行の `$` 展開と `> >> <` は CCP と同じに効く(`DIR X >O.TXT` でファイルができることを確認)。**パイプ `|` は解釈しない**(`|` 以降は子の引数)。子のコマンド行にリダイレクトがあったときだけ、子が終わると閉じる。親がリダイレクト中でも、E5h から戻ったあと親の出力は同じファイルへ行く(`tests/execrd.asm`)。印は E5h に渡したコマンド行の文字(引用符 `"` の中は除く。`HND_REDIR` と同じ規則)を見るだけなので、`$変数` の展開で現れた `>` `<` は数えない(`tests/execrd.asm` で `DIR "X>Y"` を確認)。
- **未対応(親に残る)**: 子が変えたカレントディレクトリ(`cd`)、子が開いたまま閉じなかったファイルのハンドル、環境変数(`set`)は、子の終了後も残る。`.BAT` の実行は未対応(バッチの状態は1つしか持てない)。
- **注意**: 子が使う IOCS(RST 18H)はゲートがプロセスのマップ表(`UMAP`)から戻すので動くが、子の中での試験は `UMAP` テスト(親のプロセスで差し替えたマップ)までで、E5h の子から IOCS を呼ぶ試験(`exectest` P6)は通っている。
- **しくみ**: 親の状態(UMAP・SP・IFF・DMA・予約)を記録(`PROCS`、32バイト×4)へ保存 → 子のページ7枚を空きから選んで「持たれている」印(`PGHELD`)を付ける → 子のバンク0のページへ親のゼロページを写す → UMAP を子の表にしてバンク0-4 を反映 → `HND_RUN`(CCP と同じ経路)で起動。子が終わると `UWBOOT` が `PDEPTH`(0以外)を見て `PEXIT` へ → 記録から親の状態を戻し、`UXRET`(ゲートの戻り `UGRET`)で親の E5h 呼び出しの続きへ。
