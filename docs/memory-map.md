# メモリ(MMU)の使い方と空き容量の変化 — LSX-Dodgers MZ-2500 版

最終更新: 2026-11-08(out40 時点の本文 + lsx-mmu ステージ1の追記)。数字は `build.py` が出す `body25.map` と `LD2500.BIN` の実測。
**エミュレータでの確認だけで、実機は未確認**(特に B5h の読み出し副作用、ページ 0Eh が空きか、CRTC レジスタ 8 の挙動)。

> **2026-11-08 追記: この作業ツリー(lsx-mmu)はステージ1で配置が変わった。** 以下の §2・§4・§5 は安定版(out40)の説明で、lsx-mmu では次の通り。詳細は `docs/mmu-stage1.md`。
> - ユーザプログラムの実行中は バンク5=ページ04、バンク6=ページ05(カーネル実行中は 0Bh / 06)。バンク7(0Fh)は共通。
> - **TPA = 0100H-DFFFH(約56KB。56,750B の COM を実行して確認)**。`(0006H)`=E000H。BDOS は 0005H→E000H(`JP UGATE`)から入る。
> - カーネル専用 RAM(カーネル時のバンク5 A000H-B005H): EDBUF A000H、DTBUF A600H、STAGE AA00H、スタック AE00H-B000H。
> - 常駐コード末尾 `AT_TABLE` は ED4A〜EDCC(80col。ゲートとスタブを含む)、`TABLEAD`=EDD0H。
> - バンク7 F000H 台(WORKAD)の変数と拡張BIOS表は共通。表のエントリは `CALL UXG` のスタブ(§mmu-stage1)。

## 1. MMU の基本(確認済みの仕様は `docs/hardware-notes.md`)
- CPU の 64KB を 8KB × 8 バンクに分ける。`B4h`(W)=バンク番号(bit0-2)、`B5h`(R/W)=そのバンクに割り当てるページ(bit0-5)。
- **`B5h` は書いても読んでも `B4h` が +1 される**(エミュレータ。実機は未確認)。→ 読んだら必ず `B4h` を選び直す(§5-40 で間違えて F: のテスト13本が落ちた)。
- ページ番号: 00-0F = メイン RAM 128KB、10-1F = 拡張 RAM(128KB。F: が使う)、34-37 = IPL ROM、38 = テキスト VRAM/属性、39 = PCG、3A = 辞書。
- IOCS 呼び出し(`RST 18H`)の間は、バンク1-3 が ROM に替わり、バンク6 が VRAM になる。→ その間、スタックとバッファをそこに置かない。IOCS は戻りで MMU から読んだ値で復元する。

## 2. LSX 実行中のバンク割り当て(通常時)
バンク4-7 のページ(0Ah/0Bh/06/0Fh)は `M25DEF`/ビルド設定から確認した値。**バンク0-3 の 00-03 は恒等割り当てという前提で、この表を書くために改めて測ってはいない。**
| バンク | アドレス | 通常のページ | 中身 |
|---|---|---|---|
| 0 | 0000-1FFF | 00 | ページ0・TPA 先頭(0100H から) |
| 1 | 2000-3FFF | 01 | TPA(F: の窓に一時的に使う) |
| 2 | 4000-5FFF | 02 | TPA(IOCS 退避の読み書きで一時的に使う) |
| 3 | 6000-7FFF | 03 | TPA(F: の窓の第2候補) |
| 4 | 8000-9FFF | 0Ah | TPA。**オーバーレイの窓**(使う間だけ 0Eh を割り当てる) |
| 5 | A000-BFFF | 0Bh | TPA の末尾(〜B005H)+ BDOS 本体(B006H〜) |
| 6 | C000-DFFF | 06 | 本体コード・ワーク。IOCS 中は VRAM |
| 7 | E000-FFFF | 0Fh | 本体コード末尾・編集バッファ・キー表・ワーク(F000H〜) |

## 3. ページの使い分け
| ページ | 用途 |
|---|---|
| 0Ch, 0Dh | 起動時に退避した IOCS の RAM(0000-25FFH)。`MON` で IOCS を呼ぶとき書き戻す |
| 0Eh | オーバーレイ置き場(8KB 1枚。`MODE` `SET` `ENV` が入っている。使用 488B)。他で使われていないことを grep で確認しただけ |
| 10h-1Fh | F:(RAM ディスク 128KB)。E: は EMM(ポート I/O。ページとは別) |
| 38h | テキスト VRAM(バンク6か7に出し入れ)。3プレーン(E000/E800/F000 の各 2048 セル) |

## 4. アドレス空間の配置(out40)
| 範囲 | 内容 |
|---|---|
| 0100-B005H | TPA(約44KB。外部 COM はここで動く) |
| B006H〜 | BDOS / CCP / ハンドル層 / 環境変数 / バッチ / パイプ / 行編集 など常駐コード(`AT_TABLE` まで) |
| 〜E756H(`AT_TABLE`) | 常駐コードの末尾(out40・80col の場合。80col_noiocs は E782H) |
| E850H〜EDA8H | `EDBUF`: 行編集の履歴・候補などのバッファ(イメージには入らない) |
| EDD0H〜 | キー表 5枚(560B) |
| F000H〜 | ワーク(`WORKAD`) |

TPA の作業領域(外部 COM が使う): 3C00-3FFF = 共通部品の入出力バッファ、4000H〜 = 各コマンド固有(cp/du/find は 5000H〜 にサブディレクトリの収集領域を深さごとに 200H ずつ)。`VNORM` は 4000-43FFH を回転の退避に使うので**その間だけ壊す**。

| 時点 | TPA | 常駐の空き | 備考 |
|---|---|---|---|
| 初期 | 0100-CF05(約52KB) | 本体 CF06-EFFF の範囲 | 窓を置ける空きアドレスなし |
| BDOS を C006H へ | 約48KB | 約3.9KB | §5-32 |
| §5-33(環境変数・バッチ) | 約48KB | 約115B | ENVSZ 384→256 で一時 +128 |

| §5-41 オーバーレイ(`MODE` を移す)out31→ | 約44KB | E800H まで **192B**(out31 の実測) | `LD2500.BIN` 16028B → 24576B(32+16セクタ) |

**訂正(2026-11-14)**: 上の表の「常駐の空き」は `build.py` の検査が `LNBSS`(長いファイル名用の作業領域、108B)を数えていなかったため、108B多い。E5h の取り込み後の実測は 80col_noiocs で 6B、他は 50B。

読み方: 「常駐の空き」は `EDBUF` の手前までの余り。**out40 で SET/ENV を移して 250B/206B まで戻したが、少ない。**
- `EDBUF` のずらしはもうほとんど効かない。`EDBUF` 領域の終わり(EDA8H)と `TABLEAD`(EDD0H)の差は **約40B**。
- 常駐に足すなら、(a) オーバーレイ(CCP からしか呼べない内部コマンド向き)、(b) 外部 COM、のどちらか。TPA のプログラム実行中にも使う機能(BDOS 関数、行編集)は常駐に置くしかない。
- オーバーレイの置き場は 8KB 1枚のうち `MODE` `SET` `ENV` が使っている分(488B)以外が空き(実使用量は `build.py` が出す)。ページは 0Eh のほかにもう1〜2枚足せる(ローダの読み込みを3ページ目まで広げる改造が要る)。

## 6. オーバーレイの制約(§5-41)
- 窓はバンク4(CCP のスタックがバンク5にあるため)。TPA のプログラムが走っている間は使えない(窓の位置に TPA があるため)。CCP の内部コマンド専用。
- オーバーレイから IOCS を呼ばない。呼び出しは `OVLCALL`(A=番号<<5|入口番号)。BC/DE/HL は素通し。
- `LD2500.BIN` = システム部(最大32セクタ)+ オーバーレイ(8KB=16セクタずつ)。ローダの `RDLSN` は LSN が 256 未満の範囲だけ。

## 7. 窓(MMU を一時的に動かす)コードの規則(`M25MEM.ASM` 先頭にも記載)
1. 窓にしてよいのは、バッファが隠れないバンク(F: は バンク1、バッファが触れるときはバンク3)。
2. 窓にする前に `B5h` から元のページを読んで保存し、閉じるときに書き戻す(読んだら `B4h` を選び直す)。
3. 窓の間は `DI`。スタックを使わない(開閉をサブルーチンにしない)。
4. IOCS 中はバンク1-3 が ROM、バンク6 が VRAM。

## 7. 常駐の空きを増やす(2026-11-12): 初期値の要らない作業領域を詰め物の中へ
- 本体(B006H-DFFFH)は `M25GATE.ASM` の `DEFS 0E000H-...` で E000H に揃えてあり、その手前が一杯になるとビルドが止まる(`integer range`)。`build.py` は「resident body free before E000H」を表示する。
- 初期値が要らない作業領域 `HSLOTS`(288B) `OUTBUF`(128B) `RFNAME`(64B) と `ENVBUF`(256B。起動時に0=空の環境)を、本体の外 `AT_TABLE`..`TABLEAD` の詰め物(イメージに入らない)の末尾へ移した(`M25DEF.ASM` の EQU)。INIT が0で埋める。`AT_TABLE <= BSSLOW`(RFNAME)を `build.py` が確かめる。**本体の空きが約20-30B → 約750-800B**(ENVBUF 込み)、詰め物の空きは約1000B → 約300B。
- `EDBUF` は A000H(カーネル時のバンク5の空き)にある。上の表の EDBUF=E800H は古い記録。
- さらに常駐を空けるなら: CCPだけから呼ばれる内部コマンドのオーバーレイ化(オーバーレイは8KB中7.8KB使用済み。2枚目はページ09h(E5h EXEC のオーバーレイ1)に使った。3枚目以降は 07h-08h の空きページを使う → その分は `ramdisk` で拡張RAMを空ければ補える)。
