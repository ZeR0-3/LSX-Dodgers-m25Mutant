# 実機確認 HWCHECK.COM(エミュレータでしか確認していない前提を、実機で確かめる)

`tests/hwcheck.asm`(`HWCHECK.COM`)。何も壊さない診断で、画面に出る `HW:` の行を報告に使う。**実機での結果はまだ得ていない**(エミュレータでの自己確認のみ。下の「エミュレータの値」)。
使い方: D88 に `HWCHECK.COM` を入れ(`tools/d88_put.py IMG hwcheck.bin HWCHECK.COM`)、`ramdisk 64` で F: を縮めてから `hwcheck`。縮めなくても E5h 以外は動く。
書き込むのは「E1h が空きと返した 07h-1Fh のページ」の先頭と末尾の1バイトずつ(と、実行テスト用に +10H から3バイト)だけ。F: や他のプログラムのページには書かない。

| 行 | 何を確かめるか | 外れたとき(意味) |
|---|---|---|
| `HW:SYSINFO` | E0h の値(feat/emm/f_pages/ver/tpa)。ver=03、tpa=E000 | ver<3 は古いOS(E5h なし) |
| `HW:B5 ... read-inc / write-inc` | B5h を読む/書くと B4h(バンク選択)が +1 されるか。エミュレータは両方 yes | **実機が no なら**: コードは「読んだら B4h を選び直す」ので動くはずだが、`B5h` の読み書き順に依存するコード(未確認)を見直す。bank4 が 0A でないなら OS のマップ前提が違う |
| `HW:free pages` | 07h-1Fh のうち空き(E1h=0)の数。`ramdisk 64` で 10、既定で 2 | 数が違えば F: の大きさか E1h の判定がずれている |
| `HW:pattern ok=N/M bad:` | 空きページにページごとに違う値を書いて読み戻す。別名(アドレスの折り返し)や欠け(拡張RAMが無い)があれば bad にページ番号が出る | **bad が出たページは使えない**(拡張RAMの欠け/別名)。07h/08h が bad なら IPL ROM/IOCS が使っている可能性 |
| `HW:exec from page ... 07=5A 08=5A 18=5A` | 空きページをバンク2(4000H)に出して中のコードを実行できるか(`ld a,5Ah / ret`)。10h 以上は最初の空き1枚 | 5A 以外/止まる: **拡張RAMのページをコード実行に使えない**。E5h で子の TPA に拡張RAMが入ると動かない(F: を `ramdisk 0` にして 07h/08h と 09h-0Fh だけで足りるかを検討) |
| `HW:clock` | BDOS 2Ah/2Ch の日時。**実際の時刻と見比べる**(年は16進: 07EA=2026) | ずれるなら RP5C15 の読みの前提(ポート CCh、24時間表示、レジスタ位置)が違う |
| `HW:pattern after BDOS calls` | 上のパターンが、BDOS・画面出力をはさんだあとも残っているか | 減っていたら、BDOS や IOCS がそのページを使っている(使われているページは空きではない) |
| `HW:E5h result A=00 parent ... intact` | E5h で `DIR` を子として動かし、親の 8000H-9FFFH が無傷で戻るか | `A=F0h` は空きページ不足(`ramdisk 64` を忘れた)。`BROKEN` は親が壊れた=重大。止まる/画面が崩れるなら、最後に見えた `HW:` の行を報告 |

エミュレータの値(実機との比較用): `read-inc=yes write-inc=yes`、`bank4=0A`、`pattern ok` が全部一致、`exec` は全部 5A、E5h は `A=00 intact`。
**結果が止まったら**、止まる直前に出ていた `HW:` の行(そこまでのどれか)が手がかりになる(出力は1項目ごとに順に出る)。

## 配置の自動検査(同じ時期の追加)
`tools/layout.py` を `build.py` が呼ぶ。固定アドレスの領域(カーネル時のバンク5・本体コードと作業領域・共通バンクの変数)が重ならないことを、ビルドのたびに確かめる。領域の大きさはソースを読んで書いた表で、**領域を足したら表にも足す**。既知の重なりは `WAIVE` に理由つきで書く(今は1件: 下)。
- **ゲートの変数(GVARS+0..+41 十進)とゲートのスタック(GVARS+10H..+3FH)が重なる**(元からの配置)。スタックの上端は +40H で、変数の末尾は +29H なので、変数を壊さずに使えるスタックは約22B(11段の PUSH)。ゲート実行中の最大の深さは**未計測**。
