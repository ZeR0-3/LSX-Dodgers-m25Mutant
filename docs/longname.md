# 長いファイル名(Human68k / TwentyOne 方式) — 設計メモ

## 方針
Human68k 本来の名前の持ち方を採用する。**ディスク形式は変えない**(FAT12 のまま)。ディレクトリエントリ(32 バイト)の**予約領域(+0Ch から 10 バイト)に名前の 9 文字目以降**を入れる。Shift_JIS のまま(Unicode との変換表は不要)。X68000 の Human68k(TwentyOne 常駐時)で作ったディスクと名前を相互に読み書きできる形にする。

## ディレクトリエントリでの並び
| 位置 | 内容 |
|---|---|
| +00h 8 | name1(先頭 8 バイト。余りは 20h) |
| +08h 3 | ext(拡張子。余りは 20h) |
| +0Bh 1 | 属性 |
| +0Ch 10 | **name2**(9 バイト目以降。余りは 00h) |
| +16h 2 / +18h 2 | 更新時刻 / 日付 |
| +1Ah 2 / +1Ch 4 | 先頭クラスタ / サイズ |

名前全体 = name1(後ろの空白を除く)+ name2(00h まで)。拡張子があれば `.` + ext。長さは**バイト数**で最大 18(+ 拡張子 3)。全角は 2 バイト。

## TwentyOne の資料から分かったこと(仕様。コードは写さない)
- 名前は name1+name2 の 18 バイトまで、ext は 3 バイトまで。名前に含められるピリオドの扱い:DOS 式拡張子(1〜3 文字)が最後に付くときは「18 + `.` + 3」、そうでなければ全体で 18 まで。
- Human68k 純正は 21 文字全体を区別して比較しない。TwentyOne は検索を 21 文字全体で行い、大文字小文字の区別(オプション)・ピリオド複数・記号を可能にする。
- VFAT は読み取りだけ(VTwentyOne.x)。Unicode→Shift_JIS 変換後に 18+3 へ削る。書くと拡張名が壊れる。LSX では扱わない(別バージョンの課題)。

## LSX の注意点
- **LA バイナリ**(L-os Angeles)は予約領域を別用途で使う(+10h=A0h が印)。印があるエントリは name2 を持たないものとして扱う。
- FCB は 8+3 の 11 バイトなので、既存の CP/M プログラムは name1+ext しか見えない。先頭 8 バイトが同じ名前が複数あると、最初に見つかったものが選ばれる。
- 大文字小文字: LSX は入力名を大文字にして比べる。小文字を保存する Human68k 側のディスクを読むときの扱いは、実装時に決める(まずは表示はそのまま、比較は大文字小文字を同一視)。
- PC では先頭 8 バイトと拡張子が同じ名前が重複して見える。

## 実装(2026-11-13: 表示・検索・作成・名前変更・削除まで実装、エミュレータのみで確認)
OS 本体(常駐部。`src/M25LN.ASM`)が name2 を扱う。FCB には 11 バイトしか入らないので、ファイル名の解析(BDOS 29h)が拾った name2 を、**FCB の住所をキーにした 4 枠の小さな表**に覚える(枠は FCB の名前が今も同じ間だけ有効)。
- **解析**: `FILED` の 9 文字目以降を `LNCAP` が最大 10 バイト拾う(`*` 以降は全部 `?`)。`ls`/`dir` の表示は従来どおりオーバーレイ(`M25LNAME`)。
- **比較**(検索・open): 名前の先頭 8 バイトに `?` があれば name2 は比べない(一覧用)。それ以外は、パターンの name2(無ければ空)と、エントリの name2(有効でなければ空)を大文字小文字無視で比べる。**短い名前は長い名前のファイルに一致しない**(`LONGNAME.TXT` と `LONGNAMEISHERE.TXT` は別)。
- **作成・名前変更**: name2 を大文字にしてエントリの +0Ch へ書く。LA バイナリ(+10h=A0h)のエントリは触らない。
- **削除・名前変更のワイルドカード判定**: name2 に `?` があれば複数扱い。
- **有効な name2 の条件**(Windows が予約領域に入れる値を取り違えない): 名前 1 の 8 バイト目が空白でない/+10h が A0h でない/先頭が 00h でない/00h までが 20h 以上(7Fh・FFh を除く)/00h のあとは最後まで 00h。
- **付属コマンド**: `cp`(ワイルドカード・`-r` 含む)・`egrep`・`sed`(ワイルドカード)・`find`・`du`・`which` は、検索結果から名前を作り直すときに name2 も足す(`coms/lnd.inc` の `ln_ok`/`ln_app`)ので、長い名前を保ち、同じ先頭8文字の別ファイルや別ディレクトリを取り違えない。`find`・`du` の階層ごとの収集は1件 21 バイト×20件(以前は 11 バイト×40件)、`egrep`・`sed` のワイルドカード一覧は 32 バイト×20件(以前は 16×40)。`mv`・`cat`・`type` は引数を解析して渡すだけなのでそのまま動く。
- **制限**: 長い名前を開けるのは、LSX 自身(CCP の `type` `ren` `del` `copy`、リダイレクト、`ls` `dir`)と、ファイル名の解析(29h)でパスを渡す COM。検索結果の名前から FCB を作り直す COM(name2 を持たない)は、長い名前のファイルを開けない。CP/M の COM は 8+3 の範囲しか見えない。
- **未確認**: 実機(エミュレータのみ)。VFAT は別バージョンの課題。

## 試験用
`tools/d88_put.py image.d88 file NAME.EXT [name2]` で name2 付きのファイルをイメージへ書ける。

## 補足: find の起点 `.\`(2026-11-13)
`find .\` は、BDOS の `.` 成分が親を指す癖のため、カレントの下で DEEP\DEEP\DEEP… と降り続けた。起点の先頭の `.\`(`./`)は取り除き、省略(カレント)と同じにした。`find .` は元から同じ扱い。

## BDOS E4h(登録)
プログラムが検索結果から FCB を作り直すときは、E4h(DE=FCB、HL=name2 の10バイト)で name2 を結びつけてから開く。仕様は `docs/page-api.md`、例は `tests/lnreg.asm`。
