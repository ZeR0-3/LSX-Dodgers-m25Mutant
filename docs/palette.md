# MZ-2500 のパレット(4096色ボード MZ-1M10)の使い方 — 他のAI/プロジェクト向けメモ

この文書だけで、アプリ(COM やエディタ)から色を変えられるように書いてある。実装の実物は `coms/pal.asm`(LSX-Dodgers MZ-2500 移植)。

**確認状況**: すべてエミュレータ(mz2500-web-emulator の CLI、実IPL ROM つき)での確認。**実機では何も確認していない。** MZ-1M10 ボードが実機に付いているか、ここに書いた OPN ポートA bit2 の意味が実機で同じかは未確認。根拠はエミュレータのソース(`core/renderer.cpp` `core/mz1m10.h` `core/mz2500.cpp`)の記述。

## 1. 仕組み

| もの | 内容 |
|---|---|
| パレットRAM | 16エントリ × RGB444(各成分 0-15)。エントリ0は黒固定で書けない |
| 書き込み | `OUT (0AEh)` を **BC の B 側(上位バイト)で番号を指定**して行う(下の式)。自動増加なし |
| 有効にする条件 | **OPN レジスタ 0Eh(ポートA)の bit2 = 0**。1 ならデジタル8色(従来)。0 にした瞬間から画面全体(文字もグラフィックも)がパレットRAMの値で描かれる |
| OPN の入出力 | アドレス `C8h`、データ `C9h`。レジスタ 0Eh の読み出しは(出力方向のとき)ラッチ値。**同じレジスタの bit1 は FD の内蔵ドライブ切替、bit3 はマウスの切替なので、bit2 以外は読み出した値のまま書き戻すこと** |
| 初期値 | 起動後のRAMには「ファームウェアの表」(色1-7=レベル7、8=3、9-15=15、G/R/B が色番号の bit2/1/0)が入っている(エミュレータの実IPL起動で確認)。実機は未確認 |

### パレット書き込み(エントリ n = 1-15)

```
色の R,G,B を 0-15 とする
OUT (0AEh) with B = n*2     A = (R << 4) | B      ; 偶数: 赤の上位ニブル + 青の下位ニブル
OUT (0AEh) with B = n*2+1   A = G                 ; 奇数: 緑
```

Z80 では `ld b,n*2 : ld c,0aeh : out (c),a`(`OUT (C),A` は B を A15-A8 に出す)。

### ボードのパレットを有効/無効にする(OPN 経由)

```
wait:  IN A,(0C8h) ; bit7=1 の間待つ(busy)
OUT (0C8h),0Eh     ; レジスタ選択
wait
IN  A,(0C9h)       ; 現在のポートA
AND 0FBh           ; bit2 を 0 に(有効)。無効に戻すなら OR 04h
OUT の前に再度 wait
OUT (0C8h),0Eh / wait / OUT (0C9h),A
```

## 2. 色番号(テキストの場合)

- 文字属性の下位3ビット = 色番号 = **GRB**(bit2=G, bit1=R, bit0=B): 1青 2赤 3紫(R+B) 4緑 5水色(G+B) 6黄(G+R) 7白。0 は黒。
- 表示にはこの番号にさらに**強度ビット(+8)が付いたエントリ(9-15)が使われる**ことが多い(LSX の既定の文字はそう)。確実に変えたいときは **1-7 と 9-15 の両方**に同じ色を入れる。エントリ8は暗いグレー(3,3,3)。
- LSX の `ESC b n` は ANSI 順(0黒 1赤 2緑 3黄 4青 5紫 6水色 7白)で、ハードの色番号とは違う。LSX が変換する。`pal N RGB` の N は**ハードの色番号**。

## 3. 使い方(LSX 上のコマンド)

```
pal            標準(デジタル8色)に戻す
pal soft       柔らかい色(文字色: 緑=(9,15,9) 白=(12,12,12) など)
pal N RGB      色N(1-15)を RGB(16進3桁 0-F)にする。例) pal 12 8F8
```

- `mode 40` / `mode 80`、`cls`、`dir` のあとも色は保たれる(エミュレータで確認、テストあり)。IOCS の初期化を通る操作(IOCS のモニタ `imon` など)でポートA bit2 が戻るかは未確認。
- ボードが無い機械では OUT (0AEh) は何も起きない想定(エミュレータでは無視される)。OPN の bit2 は書き換わるが、デジタル表示のままになるはず(実機未確認)。

## 4. アプリに組み込むとき

1. **LSX の上かの判定は先に**: `C=6Fh` で機種IDを見る(`docs/app-memory-guide.md` 4節)。他のOSでこの I/O を叩かない。
2. 書き込みは割り込み中でも1命令なので安全だが、OPN の bit2 の読み出し→書き戻しの間に IOCS(割り込み経由で OPN の同じレジスタを使う)が割り込むと、他のビットを巻き戻す恐れがある。**DI〜EI で挟む**か、IOCS を呼ばない区間で行う。(`pal.asm` は挟んでいない。エミュレータで問題は出ていないが、実機の安全のためにはアプリ側で挟むのが無難。)
3. 色を戻すときは bit2 を1に戻すだけでよい(パレットRAMは書き換えたままでよい)。
4. グラフィック(GVRAM)の色も同じパレットを通るので、ボードの有効化はグラフィックにも効く。16エントリ全部を埋めてから有効にする(未書き込みのエントリは黒になる恐れ)。

## 5. エミュレータでの確認方法

```
$LSX_CLI --real-ipl --rom-dir <ROM dir> --disk-a LSX2500_80col.d88 --frames 700 \
  --type 'pal soft\r:450' --type 'ls\r:550' --screenshot a.ppm
```
`a.ppm`(640x400)のピクセル値で確認する。標準: 緑 (0,255,0)、白 (255,255,255)。`pal soft` 後: 緑 (144,240,144)、白 (192,192,192)。テストは `tools/test_all.sh` の「pal.COM」。
