# E5h EXEC(子プログラムの起動)と、その土台の UMAP

> エミュレータ(実IPL ROM つき)での確認のみ。**実機は未確認**。`lsx-mmu` に取り込み済み(2026-11-14)。安定版(proj/out40)には入っていない。
> 呼ぶ側(アプリ)向けの仕様は `docs/page-api.md` の E5h の節と `docs/app-memory-guide.md` の 9 を参照。

## 目的
`:!cmd`(エディタから外部コマンドを動かして戻る)と統合環境のために、**親のメモリを動かさずに子を 0100H で起動し、終わったら親へ戻す**。CP/M の COM は 0100H 固定で再配置できないが、MZ-2500 の MMU は 0100H の裏の物理ページを替えられるので、子には空きページ7枚を出して動かす(コピーなし)。

## 設計
- **プロセスの表 `UMAP`**(共通バンク `FF17H-FF1DH`、バンク0..6 のページ)。ゲート/IOCS戻り/UCPIN/`MON_UNMAP` がここから読む。初期化は `M25INIT.ASM` の `INIT1` で FF00H-FFFFH を0にした直後。`PDEPTH`(`FF1E`)= 子の深さ。
- **E5h(`RS_EXEC`、`M25OVL.ASM`)**: コマンド行を STAGE へ → オーバーレイ1 の入口0(`PR_EXEC`、`M25PROC.ASM`、ページ09h)で ①深さ(4まで)②空きページ7枚 ③親の状態(UMAP・SP・IFF・DMA・予約`PGUSER`・`PGHELD`)を `PROCS`(A580H、32B×4。記録の +27 は「この子のコマンド行に `>` `<` がある」印)へ保存 ④子のバンク0のページへ親のゼロページを写す ⑤親の予約と子のページを `PGHELD` へ ⑥UMAP=子の表 → 常駐で `SETBK04` → 子の 0080H にコマンド行を作り、`HND_EXPAND`(`$`展開)・`HND_REDIR`(`> >> <`)・`HND_RUN`(CCP と同じ経路)。COM は `ULAUNCH` へ(戻らない)。内部コマンドは戻って `PEXIT`。
- **子の終了**: `jp 0`/BDOS 0/62h は `UWBOOT` へ。`PDEPTH`≠0 なら `PEXIT`(オーバーレイ1 の入口2 `PR_RST` が、子のコマンド行にリダイレクトがあったときだけ `HND_RESET` で閉じる=親のリダイレクトは残す。入口1 `PR_EXIT` で親の状態を戻す)→ `SETBK04` → ゲートの `UXRET` → 親の E5h 呼び出しの続きへ。戻り値: A=終了コード(`EXITC`)、F=0、BC=DE=HL=0。戻ったら `EXITC` を0に戻す(孫の値を持ち越さない)。
- **ページ所有**: `PG_OWNER` は `PGUSER`(今のプロセスの予約)と `PGHELD`(止まっている親の予約+子のTPA)の両方を予約済みと見る。
- **パイプ `|` は解釈しない**(`|` 以降は子の引数になる)。`.BAT` も不可。
- **カレントドライブ**はゼロページ 0004H にあるので子ごとに別。

## 設計上の判断
- 常駐の共通領域の空きは約430Bしかなく、EXEC を常駐に入れると約540B要った。準備と後始末を**2つ目のオーバーレイ(ページ09h)**に移した。**副作用: アプリ向けの空きページが 07h-09h(24KB)から 07h-08h(16KB)**。オーバーレイのページを替えるのは `build.py` の `OVL_PAGES` と `M25OVL.ASM` の `OVLPGT`。
- 常駐の残り空き(`build.py` が出す `free`): **80col_noiocs で 6B、他は 50B**。**以前の `build.py` の検査は作業領域の一番下(長いファイル名用 `LNBSS`、108B)を数え忘れていて、空きを108B多く見積もっていた**(2026-11-14 に気づいて `LNBSS` を使うよう直した。それ以前の資料の「常駐の空き」の数字は108B引いて読むこと)。この検査漏れのせいで、コードが `LNBSS` に食い込んでも ビルドが通り、80col_noiocs だけ起動後に画面が崩れた(E5h のリダイレクト対応で見つかった)。**常駐にはもう足せない。足すならオーバーレイ(ページ09h のオーバーレイ1は使用量が小さい)へ**。
- 失敗時の `SHOW_ERROR` も最後は `JP 0` なので `PEXIT` に着く。
